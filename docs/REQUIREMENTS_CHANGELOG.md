# 需求变更记录与优先级决策依据

## 1. 文档定位与维护约定

本文件以**简要记录**为原则，不替代 Git 提交记录或完整产品设计文档，旨在后续迭代出现新旧需求冲突时，快速提供**优先级判断**与**历史决策依据**。

维护规则：

1. 新增、调整或推翻需求时，按递增编号 `REQ-XXX` 追加一条简要记录。
2. 若新变更影响到已有需求，必须在「关联 / 替代」中标注受影响的旧编号，并将旧条目状态更新为 `已部分调整`、`已被替代` 或 `已废弃`。
3. 纯代码重构、样式微调或无产品行为变化的工程琐事不记入本文件。

## 2. 优先级分级与冲突决策原则

### 2.1 优先级分级

| 级别 | 定位 | 涵盖范围 |
|---|---|---|
| `P0` | 产品底线 | 纯本地零网络、低资源占用（无高频轮询 / 无重型运行时）、数据不丢失与磁盘安全（自动保存、历史保留、日志封顶）、绿色便携单文件可运行、严守非目标边界（不做账号登录、云同步、多人协作、复杂项目管理 / 甘特图、AI 等）。 |
| `P1` | 核心主路径 | 每日 / 每周工作计划核心 CRUD、进度 `[0, 100]` 与状态联动、日周关联与等权自动汇总事务一致性、非破坏性幂等结转、系统托盘可靠驻留与主窗口秒级唤出/收起。 |
| `P2` | 高频增强 | 历史记录与关键词搜索、Markdown 日报 / 周报、全局快捷键、开机自启、主题切换、本地备份与恢复。 |
| `P3` | 可选增强 | 默认关闭的可选功能（如迷你悬浮窗）、次要视觉或交互微调。 |

### 2.2 冲突判定原则

1. **高优先级约束兜底**：高优先级约束（如 `P0` 产品底线、`P1` 数据一致性）默认优先于低优先级诉求；不得为满足 `P2`/`P3` 需求而牺牲 `P0`/`P1` 稳定性或性能。
2. **显式变更、禁止静默覆盖**：新需求与已生效的旧需求冲突时，必须显式记录变更原因及被调整/替代的 `REQ-XXX` 编号，禁止静默修改导致历史行为隐式回归。
3. **同级冲突取简**：同优先级需求冲突时，优先保留「高频主路径更简洁、界面负担更低、维护复杂度更小」的方案；非普适诉求优先设计为默认关闭的可选项。
4. **守住非目标红线**：与 `P0` 产品底线或 [v1.0 PRD](PRD.md)「明确不包含的功能」直接冲突的需求默认拒绝，除非显式发起产品定位调整并登记为 `P0` 级变更。

## 4. 简要变更明细

### REQ-001｜产品定位、非目标与本地化基线（2026-11-20｜基线｜P0｜生效中）

- **摘要**：PlanLite 定位为个人日常与每周工作计划管理工具，基于 C# / .NET 10 LTS / WPF / SQLite 构建，支持默认数据分离与 `portable.flag` 绿色便携双模式，明确不做账号登录、云同步、多人协作、复杂项目管理/甘特图及 AI 功能。
- **决策依据**：核心场景为 Windows 高频随手记与复盘，必须避免重型框架（如 Electron/WebView）及网络/协作复杂度对启动速度、内存和单文件分发的拖累。
- **不可破坏约束**：零网络请求、无后台高频轮询、内嵌资源单文件可运行、程序升级不覆盖用户数据、不引入非目标重型能力。
- **来源 / 关联**：[docs/PRD.md](PRD.md)、[AGENTS.md](../AGENTS.md)

### REQ-002｜核心计划模型、自动汇总与幂等结转（2026-11-20｜基线｜P1｜生效中）

- **摘要**：按自然周（周一至周日，ISO-8601）和自然日管理任务；进度 `[0, 100]` 与「未开始 / 进行中 / 已完成」自动联动；周计划支持手动与按关联每日任务等权平均自动计算；未完成任务结转至下一周期时保留历史记录并保证幂等。
- **决策依据**：日计划与周目标需要低心智负担的数据闭环，同时避免结转或删除周目标破坏历史工作留痕与既定周统计。
- **不可破坏约束**：进度变更与自动汇总必须在同一 SQLite 事务内原子生效；删除周计划保留关联每日任务并置空外键；结转绝不修改或删除原周期任务，且跨周每日结转不得回改历史周自动进度；所有修改自动落盘。
- **来源 / 关联**：[docs/PRD.md](PRD.md)、[AGENTS.md](../AGENTS.md)

### REQ-003｜系统托盘驻留与轻量弹窗交互（2026-11-20｜基线｜P1｜生效中）

- **摘要**：软件默认静默启动于系统托盘，保持单实例运行；点击托盘或快捷键在当前显示器工作区右下角弹出主窗口，支持总览/今日/本周视图、失焦自动收起与图钉固定，并通过窗口内联面板完成任务详情编辑。
- **决策依据**：工具以「即唤即用、用完即走」为核心体验，需避免占用任务栏或因弹出子窗口导致主窗口误失焦收起。
- **不可破坏约束**：默认不占任务栏（除非 `--show` 或用户主动唤出）；内联编辑与模态对话框期间不得触发失焦隐藏；跨天切换依赖零点精确事件而非高频轮询。
- **来源 / 关联**：[docs/PRD.md](PRD.md)、[AGENTS.md](../AGENTS.md)

### REQ-004｜效率增强功能与可选悬浮窗（2026-11-20｜基线｜P2｜生效中）

- **摘要**：提供按周期浏览与关键词搜索历史、一键复制或导出 Markdown 日报/周报、全局快捷键、开机自启（HKCU 注册表，无需管理员权限）、跟随系统/浅色/深色主题、`.zip` 完整备份校验恢复，以及默认关闭的桌面迷你悬浮窗（按 `P3` 可选约束管理）。
- **决策依据**：覆盖复盘、汇报与跨设备迁移刚需；将迷你悬浮窗设为默认关闭的可选项，防止额外常驻窗口干扰偏好极简托盘模式的用户。
- **不可破坏约束**：恢复备份前必须校验数据库完整性并保留恢复前安全副本；无需管理员权限即可运行与设置自启；迷你悬浮窗保持默认关闭且可独立开关。
- **来源 / 关联**：[docs/PRD.md](PRD.md)、[README.md](../README.md)

### REQ-005｜静默启动托盘图标原生注册与自动恢复（2026-11-21｜约束强化｜P1｜生效中）

- **摘要**：隐藏启动模式下，托盘图标不得依赖未显示主窗口的呈现句柄，必须通过原生 Win32 `Shell_NotifyIconW` 与独立隐藏顶级窗口可靠注册，并监听 `TaskbarCreated` 广播以在资源管理器重启后自动恢复。
- **决策依据**：`WPF-UI.Tray` 依赖未显示主窗口的 `PresentationSource` 时，静默启动会导致托盘图标无法出现在通知区域，使核心入口不可达。
- **不可破坏约束**：主窗口尚未显示或隐藏期间，托盘图标必须稳定可见且左/右键交互可用；资源管理器重启后必须自动重新注册托盘图标并正确释放图标句柄资源。
- **来源 / 关联**：commit `5e9878f`，细化 `REQ-003`

### REQ-006｜展示控件只读绑定与异常日志磁盘封顶（2026-11-21｜约束强化｜P0｜生效中）

- **摘要**：所有只读统计/展示型进度条统一采用 `Mode=OneWay` 绑定，避免写入只读属性引发 `XamlParseException`；异常日志增加 10 秒同异常冷却折叠与 1 MB 单文件轮转（封顶约 2 MB），调度器未处理异常增加防重入与 5 秒 Toast 节流。
- **决策依据**：渲染期绑定异常会反复触发重绘并造成日志文件无限膨胀，直接威胁桌面工具的长期运行稳定性与本地磁盘安全。
- **不可破坏约束**：只读视图属性禁止双向绑定；错误日志必须有去重冷却与容量上限，正常无异常时不生成冗余日志；未处理异常不得引发死循环刷新或弹窗风暴。
- **来源 / 关联**：commit `6d3e899`，强化 `REQ-001`
